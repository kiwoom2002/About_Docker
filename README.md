# About_Docker
Chapter 1
1. 서비스를 이루는 요소: 애플리케이션/ 데이터/ 인프라
애플리케이션: 사용자가 보는 화면과 그 뒤의 처리
ㄴ프론트엔드: 사용자가 직접 상호작용하는 부분, 부라우저/웹에서 실행됨  -  ex) html, css, javascript
ㄴ백엔드: 요청을 받아 처리하고 데이터를 다루는 부분, 서버에서 실행됨  -  ex) python, java, Go, Node.js
데이터: 상품, 회원, 채팅 기록 등 -> 데이터베이스에 보관
인프라: 앱&데이터가 실제로 돌아가는 컴퓨터|네트워크
ex) 서버/운영체제/클라우드

2. 서버-클라이언트의 요청과 응답
프로토콜: 통신규칙
3티어 구조: 프론트엔드-백엔드-데이터베이스
주소를 치고 화면이 뜨는과정: dns -> 연결 -> http 요청 -> 렌더링
dns를 통해 자연어로 적힌 주소를 ip주소로 전환하고 해당 주소의 서버와 연결한다. 그후 get요청을 보내 html을 응답받고, 브라우저가 html을통해 화면에 그림.
ㄴhtml이라는 단어에 집착하지말것. 서버가 보내는 것에 html만 있는것은 아님. 마찬가지로 브라우저또한 css,js를 통해서 화면을 나타내기도함.

3. 컨테이너
이미지: 앱+의존성+설정을 한 파일처럼 묶은것 -> 설계도
컨테이너: 이미지를 실행한것, 실제로 돌아가는 상자 -> 어느 서버에서든 똑같이 실행됨
쿠버네티스: 여러개의 컨테이너를 관리함. 자가복구/확장/무중단(rollout)
MSA: 하나의 앱의 기능을 쪼개어 여러 작은 서비스로 나눈것. -> 각 기능을 병렬적으로 개발가능

Chapter 2
1. 컨테이너를 사용하는 이유
여러대의 서버에서 여러 앱을 사용할때 서로 환경이 호환되지 않아서 버전충돌이 일어날 가능성이 높음. 컨테이너는 os를 직접 띄우는 방식이아니라 몇초안에 시작하고, 서버한대에 여러개를 띄울 수 있다.
또한 도커만 있으면 어떤 환경에서도 실행가능하다. 이미지를 받아서 실행만하면 앱이 실행되므로 배포가 빠르고, 확장성이좋다. 
2.vm과의 차이점
각 vm마다 개별적인 os와 자원을 제공받음 -> 자원을 안쓰더라도 다른 vm에서 사용이 불가능. 즉 효율적인 자원관리가 안됨.
컨테이너는 호스트os를 사용하고 docker engine을 이용해서 자원을 필요한만큼 사용한다.
3. 컨테이너의 사용법
1) 도커파일을 작성한다.
2) 도커파일을 빌드하여 이미지를 만든다.
3) 이미지를 실행(run)시켜 컨테이너를 띄운다.
or
1) 이미지를 레지스트리(개인저장소, 도커허브) 에서 가져온다.
2) 이미지를 실행시켜 컨테이너를 띄운다.
